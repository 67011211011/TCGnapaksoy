เกี่ยวกับระบบและวิธีใช้

TCGnapaksoy คืออะไร

TCGnapaksoy เป็นเว็บแอปตลาดประมูลการ์ดสะสม พัฒนาด้วยภาษา Go และฐานข้อมูล SQLite สมาชิกลงขายการ์ดของตัวเองเป็นการประมูล (พร้อมอัปโหลดรูปการ์ด) สมาชิกคนอื่นเสนอราคาแข่งกัน เมื่อหมดเวลา ผู้เสนอราคาสูงสุดคือผู้ชนะ ผู้ขายแต่ละคนมีหน้าร้านของตัวเอง และตั้งรูปโปรไฟล์ได้ ระบบเป็นโปรเจกต์เพื่อการศึกษา ไม่มีการชำระเงินจริง

กติกาการประมูล

  • ราคาเปิดเป็นราคาต่ำสุดของการ์ด และการเสนอราคาแต่ละครั้งต้องเพิ่มอย่างน้อยตาม "ขั้นต่ำ" ที่ผู้ขายกำหนด
  • ถ้ามีคนประมูลในช่วง 5 นาทีสุดท้าย ระบบขยายเวลาให้เป็น 5 นาทีนับจากการประมูลนั้น (กันการแย่งชิงในวินาทีสุดท้าย)
  • ผู้ขายประมูลการ์ดของตัวเองไม่ได้ และผู้นำราคาอยู่แล้วไม่ต้องประมูลซ้ำ
  • ชื่อผู้ประมูลถูกซ่อนบางส่วน (เช่น na***) ยกเว้นผู้ขายที่เห็นชื่อผู้ชนะ
  • เมื่อมีผู้ประมูลแล้ว ผู้ขายแก้ไขข้อมูล/เปลี่ยนรูป/ลบการ์ดไม่ได้ (กันสลับรูปหลอกคนที่เสนอราคาไปแล้ว)

วิธีใช้งาน

ผู้ใช้ทั่วไป (role: user)

  1. สมัครสมาชิกด้วยชื่อผู้ใช้และรหัสผ่าน (ไม่ต้องใช้อีเมล) ดูรายการประมูลได้โดยไม่ต้องล็อกอิน
  2. เลือกการ์ด ดูรายละเอียดและประวัติการประมูล แล้วใส่ราคาในกล่องประมูล
  3. ลงขายการ์ดที่เมนู "ลงขายการ์ด" กดเลือกรูปการ์ดจากเครื่อง (JPG/PNG/GIF ไม่เกิน 2MB) แก้ไขหรือเปลี่ยนรูปได้ตราบที่ยังไม่มีผู้ประมูล
  4. เปลี่ยนรูปโปรไฟล์ที่เมนูชื่อของคุณมุมขวาบน การ์ดทั้งหมดที่คุณลงขายจะรวมอยู่ในหน้าร้านของคุณ
  5. ติดตามสถานะ นำอยู่ / ถูกแซง / ชนะ ที่เมนู "ประมูลของฉัน"

ผู้ดูแลระบบ (role: admin)

  1. เข้าสู่ระบบด้วยบัญชีแอดมิน แล้วเปิดเมนู "ผู้ดูแลระบบ"
  2. ดูสถิติ ยกเลิกหรือลบการประมูลที่ไม่เหมาะสม จัดการสมาชิก (เปลี่ยนบทบาท/ลบ) และดูประวัติการประมูลทั้งหมด

ฟีเจอร์ตามเกณฑ์ขั้นต่ำ

  1. สมัครสมาชิกและเข้าสู่ระบบ: เก็บรหัสผ่านด้วย bcrypt (cost 12) มี salt ในตัว ไม่เก็บรหัสผ่านจริง
  2. สองบทบาท: user (ลงขาย/ประมูล) และ admin (ดูแลทั้งระบบ) ตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกคำขอ
  3. CRUD ที่มีเจ้าของ: "รายการประมูล" (รวมรูปการ์ด) ผู้ใช้ A แก้/ลบรายการของผู้ใช้ B ไม่ได้ เพราะ SQL ผูก seller_id จาก session
  4. ฟอร์มที่บันทึกลงฐานข้อมูลและแสดงผลกลับ: ฟอร์มลงขายการ์ด ฟอร์มเสนอราคา และฟอร์มเปลี่ยนรูปโปรไฟล์
  5. หน้าผู้ดูแลระบบ: /admin เข้าได้เฉพาะ admin (user ธรรมดาจะได้ 403)

การป้องกันการโจมตี

  • SQL Injection: ใช้ placeholder ทุกคำสั่ง SQL รวมถึงช่องค้นหา
  • XSS: template escape อัตโนมัติ และ Content-Security-Policy ที่อนุญาตเฉพาะสคริปต์ของเราเอง
  • CSRF: token ผูกกับ session ทุกฟอร์ม + Fetch Metadata + SameSite cookie
  • การอัปโหลดรูป: จำกัดขนาด 2MB ตรวจชนิดไฟล์จากเนื้อไฟล์จริง (ไม่เชื่อนามสกุล) จำกัดความกว้างยาวกัน decompression bomb แล้ว decode และ encode เป็น JPEG ใหม่ทุกครั้ง (ลบ EXIF และข้อมูลแอบแฝง) เสิร์ฟด้วย id เท่านั้น ไม่ใช้ชื่อไฟล์จากผู้ใช้ จึงไม่มี path traversal และอัปโหลดได้เฉพาะผู้ที่ล็อกอินและเฉพาะเส้นทางที่กำหนด
  • IDOR / ยกระดับสิทธิ์: ตรวจความเป็นเจ้าของใน SQL, ไม่รับ role หรือ seller_id จากฟอร์ม, เปลี่ยนได้แค่รูปโปรไฟล์ของตัวเอง
  • โกงการประมูล: ตรวจกติกาทั้งหมดใน SQL คำสั่งเดียวแบบ atomic กันการกดพร้อมกัน ใช้เวลาของเซิร์ฟเวอร์ ไม่เชื่อนาฬิกาในเบราว์เซอร์ ราคาเป็นจำนวนเต็มบาท
  • Brute force: rate limit ต่อ IP และล็อกบัญชี 15 นาทีเมื่อรหัสผิด 5 ครั้ง จำกัดความถี่การประมูลและการอัปโหลด
  • Session: token สุ่ม เก็บเฉพาะ hash ในฐานข้อมูล, cookie HttpOnly/Secure/SameSite, หมุน session หลังล็อกอิน
  • อื่น ๆ: security headers, ค่าที่เลือกได้ใช้ whitelist, timeout ของเซิร์ฟเวอร์, error ไม่เปิดเผยรายละเอียดภายใน
